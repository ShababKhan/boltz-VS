## 2024-05-18 - Optimized feature combination for HTVS mode
**Learning:** In the `combine_feats` logic, allocating `torch.zeros()` with dimensions size `N_max` and then copying `N_p` and `N_l` fragments into it creates severe CPU / memory overhead when high-dimensional tensors (like MSA features `[B, N, L, C]`) are heavily padded. This padding operation was happening redundantly for almost all keys even when `N_p == N_max` and `N_l == N_max` (the most common case, since usually ligand `N_l` is 1 and `N_p` is `N_max`). By unconditionally running `torch.zeros`, execution time per molecule grew to ~0.3s.
**Action:** Always condition sequence block zero-allocations and `F.pad()` logic on `if N < N_max`, falling back directly to `torch.cat([fp, fl], dim=2)` when unnecessary padding can be skipped. This speeds up HTVS processing significantly (by ~80%).
## 2025-02-15 - Optimized `all()` by replacing list comprehensions with generator expressions
**Learning:** Using list comprehensions inside `all()` (e.g., `all([condition(x) for x in iterable])`) forces Python to allocate the entire list in memory and evaluate every single item before `all()` even starts. This entirely breaks short-circuiting, meaning `all()` evaluates to `False` much slower if an early item fails. In molecular property checking (like checking `atom.HasProp("_CIPRank")`), replacing the list comprehension with a generator expression `all(condition(x) for x in iterable)` yielded up to a 99% performance boost during early failure scenarios (from ~0.43s per 10k iterations down to ~0.001s in benchmarks).
**Action:** In performance-critical parsing loops, always avoid intermediate list allocations inside short-circuiting functions like `any()` or `all()`. Use generator expressions to preserve early exit behavior.
